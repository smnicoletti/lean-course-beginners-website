Ripasso: definizioni e risultati disponibili

Usiamo nuovamente il tipo Naturale, la somma ricorsiva sul secondo argomento e il doppio.

Dalla Lezione 6 abbiamo:

  • somma m zero = m.
  • somma m (succ n) = succ (somma m n).
  • doppio (succ n) = succ (succ (doppio n)).
  • somma zero n = n.

Esercizio: il successore nella somma

Vogliamo dimostrare:

lecture07_succ_somma (m n : Naturale) :

somma (succ m) n = succ (somma m n).

Associatività

L'associatività dice che il modo di raggruppare tre addendi non cambia il risultato:

lecture07_somma_assoc (a b c : Naturale) :

somma (somma a b) c = somma a (somma b c).

Scegliamo c perché occupa il secondo argomento della somma esterna a sinistra.

Risultati disponibili per le dimostrazioni

Possiamo ora usare con rw:

  • lecture07_somma_zero_destra (m : Naturale) : somma m zero = m.
  • lecture07_somma_succ_destra (m n : Naturale) : somma m (succ n) = succ (somma m n).
  • lecture07_zero_somma (n : Naturale) : somma zero n = n.
  • lecture07_succ_somma (m n : Naturale) : somma (succ m) n = succ (somma m n).
  • lecture07_doppio_succ (n : Naturale) : doppio (succ n) = succ (succ (doppio n)).

Commutatività

La commutatività dice che scambiare i due addendi non cambia il risultato:

lecture07_somma_comm (a b : Naturale) : somma a b = somma b a.

Facciamo induzione su b. A sinistra è il secondo argomento di somma, mentre a destra è il primo. Useremo quindi anche succ_somma.

Che cosa fa simp?

simp semplifica applicando equazioni orientate e svolgendo computazioni elementari.

  • rw indica una precisa riscrittura.
  • simp only [lemmi] usa soltanto i lemmi elencati.
  • simp [lemmi] aggiunge quei lemmi alle regole standard.

Controllare il simp-set

Il simp-set è l'insieme delle regole disponibili al semplificatore.

  • simp [lemma] aggiunge una regola per quel comando.
  • attribute [local simp] lemma la rende disponibile nella sezione corrente.
  • @[simp] la registra per il resto del modulo.

Associatività e commutatività non indicano da sole una forma più semplice. Quando servono, le applichiamo con rw nella direzione desiderata.

Risultati per la dimostrazione conclusiva

Useremo:

  • somma m (succ n) = succ (somma m n).
  • doppio (succ n) = succ (succ (doppio n)).

Esercizio conclusivo

Vogliamo dimostrare che il doppio di una somma è la somma dei doppi:

lecture07_doppio_somma (m n : Naturale) :

doppio (somma m n) = somma (doppio m) (doppio n).

  • Su quale variabile conviene fare induzione?

Dalla matematica alla verifica del software

Un programma riceve un input e produce un output. Per verificarlo:

  • definiamo con precisione il programma.
  • formuliamo una proprietà attesa del risultato, cioè la specifica formale.
  • dimostriamo che la proprietà vale per ogni input possibile.

Gli esempi non bastano: possono mostrare un errore, ma non coprono tutti gli input. Una dimostrazione universale fornisce invece una garanzia generale.

Un tipo induttivo per le liste

Una lista di elementi di tipo α può essere costruita in due modi:

  • vuota: la lista senza elementi.
  • cons x xs: un elemento x seguito da una lista xs.

inductive Lista (α : Type) where

| vuota

| cons (testa : α) (coda : Lista α)

Il parametro α rappresenta il tipo degli elementi. La stessa definizione costruisce liste di naturali, stringhe o altri tipi. Questo riuso della stessa struttura per tipi diversi si chiama polimorfismo parametrico.

Costruire una lista

Con i costruttori possiamo rappresentare, per esempio, la lista che contiene zero, uno e due:

cons zero (cons uno (cons due vuota))

La struttura esplicita una testa e una coda:

  • la testa è il primo elemento.
  • la coda è una lista più piccola.
  • la ricorsione e l'induzione possono procedere sulla coda.

Concatenare due liste

Prima di rovesciare una lista definiamo la concatenazione:

Nel file Lean scriviamo il parametro α : Type tra parentesi graffe. Le graffe indicano che è implicito: Lean ricava α dai tipi di xs e ys.

Per un tipo α, definiamo:

def concatena (xs ys : Lista α) : Lista α :=

match xs with

| vuota => ys

| cons x xs => cons x (concatena xs ys)

La funzione analizza la prima lista. Se non è vuota, conserva la testa e concatena ricorsivamente la coda con ys.

Esempio: concatenare due liste

Per leggere più facilmente l'esempio, rappresentiamo le liste tra parentesi quadre:

xs = [zero, uno]

ys = [due]

La definizione attraversa xs da sinistra a destra:

concatena [zero, uno] [due]

= zero :: (concatena [uno] [due])

= zero :: (uno :: (concatena [] [due]))

= zero :: (uno :: [due])

= [zero, uno, due]

Qui [] rappresenta la lista vuota e x :: xs rappresenta cons x xs. È una notazione illustrativa, ma nel file Lean usiamo vuota, cons e concatena.

Un algoritmo per rovesciare una lista

Nel caso vuoto il risultato è ancora vuoto. Nel caso cons, rovesciamo la coda e collochiamo la testa in fondo:

Per un tipo α, definiamo:

def rovescia (xs : Lista α) : Lista α :=

match xs with

| vuota => vuota

| cons x xs =>

concatena (rovescia xs) (cons x vuota)

La chiamata ricorsiva usa la coda xs, che contiene un costruttore cons in meno.

Esempio: rovesciare una lista

Usiamo la notazione illustrativa con parentesi quadre:

rovescia [zero, uno]

= concatena (rovescia [uno]) [zero]

= concatena (concatena (rovescia []) [uno]) [zero]

= concatena (concatena [] [uno]) [zero]

= concatena [uno] [zero]

= [uno, zero]

La funzione rovescia prima la coda [uno], poi colloca zero in fondo.

Quale proprietà vogliamo verificare?

Una proprietà fondamentale è che rovesciare due volte restituisca la lista iniziale:

Per ogni tipo α e ogni xs : Lista α:

rovescia (rovescia xs) = xs.

Non verifichiamo soltanto una lista concreta. Il quantificatore implicito su xs richiede che la proprietà valga per ogni Lista α.

Questa è una proprietà di correttezza importante, non una specifica completa di ogni aspetto dell'algoritmo.

Proprietà verificata e specifica completa

Una proprietà verificata stabilisce un fatto sul programma. Una specifica completa dovrebbe descrivere abbastanza precisamente il comportamento atteso da escludere implementazioni scorrette.

L'equazione

rovescia (rovescia xs) = xs

non basta da sola. Anche la funzione identità, che restituisce sempre xs senza rovesciarla, soddisfa la stessa equazione.

Per caratterizzare meglio rovescia servono altre proprietà, per esempio:

rovescia (concatena xs ys) =

concatena (rovescia ys) (rovescia xs).

Lemmi utili per la proprietà finale

Prima di dimostrare rovescia (rovescia xs) = xs, dimostriamo alcuni lemmi che ci saranno utili:

  • concatena xs vuota = xs.
  • concatena (concatena xs ys) zs = concatena xs (concatena ys zs).
  • rovescia (concatena xs ys) = concatena (rovescia ys) (rovescia xs).

Verificare rovescia

Per dimostrare rovescia (rovescia xs) = xs facciamo induzione su xs:

  • caso vuota: la definizione si riduce direttamente.
  • caso cons x xs: apriamo rovescia.
  • usiamo il lemma su rovescia e concatena.
  • usiamo l'ipotesi induttiva sulla coda xs.

La forma del dato guida sia l'esecuzione dell'algoritmo sia la sua dimostrazione.

Che cosa abbiamo verificato?

Abbiamo collegato tre livelli:

  • struttura dei dati: i costruttori vuota e cons.
  • programma: le definizioni ricorsive concatena e rovescia.
  • proprietà di correttezza: proposizioni dimostrate per ogni input.

In Lean programmi e dimostrazioni convivono nello stesso linguaggio, e il kernel controlla entrambi.

Strategia operativa

  • Leggiamo quale argomento è analizzato dalla definizione.
  • Proviamo se il goal si riduce con rfl.
  • Usiamo con rw le uguaglianze già dimostrate.
  • Se resta una variabile nell'argomento analizzato, consideriamola per l'induzione.
  • Automatizziamo con simp only o simp.
